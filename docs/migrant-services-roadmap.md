# 移工服務構想 — 決策文件

**目的：** 盤點所有可能的移工服務構想，分類、評估、決定做哪些、用什麼形式做。

**核心原則：**

1. **別重造輪子** — 別人做得比我們好的，就連結過去
2. **延伸手冊優先** — 既有 app 的小延伸比新 app 容易十倍
3. **風險控管** — 涉及法律/醫療/金融建議的功能必須極度小心

## 分類清單

### 🟢 第一批：延伸現有手冊（建議立刻做）

這些不需要新 app，直接在 disaster-handbook 上加。

| 功能                         | 說明                                                                     | 投入   | 風險            |
| ---------------------------- | ------------------------------------------------------------------------ | ------ | --------------- |
| **移工模式開關**             | 在首頁勾選「我是移工」，表單欄位自動調整                                 | 半天   | 低              |
| **PDF 加入 1955 / 113 專線** | 勾選後 PDF 自動加入勞工/婦幼專線 + 母語使用教學                          | 1 天   | 低              |
| **雇主 / 仲介聯絡欄位**      | 表單增加雇主名稱、電話、仲介名稱、電話                                   | 2 小時 | 低              |
| **駐台辦事處資訊**           | PDF 加入越 / 印 / 泰 / 菲 駐台辦事處電話 + 地址                          | 2 小時 | 低              |
| **急診求助詞彙卡**           | PDF 加入一頁常用緊急詞彙（「我受傷了」「請叫救護車」「我過敏」）四語對照 | 1 天   | 中 — 翻譯需校對 |
| **外籍移工健康服務中心地圖** | 把衛福部「外籍移工健康服務中心」資料加入 medical 搜尋                    | 半天   | 低              |

**完成度：** 這 6 個全做完大約 3-4 天，可以一次上線。

---

### 🟡 第二批：獨立工具 / 子頁面（值得做但需要設計）

這些適合放在 disaster-handbook 底下的子頁面，或獨立的小網站。

| 功能                             | 說明                                                   | 為什麼值得                | 難度       |
| -------------------------------- | ------------------------------------------------------ | ------------------------- | ---------- |
| **離線緊急按鈕頁**（/emergency） | 一頁式大字按鈕：119/110/1955/113/駐台辦事處，離線可用  | 極度有用，緊急時 1 秒可用 | 半天       |
| **1955 案件自助紀錄**            | 表單記錄時間、地點、內容、證據照片；純工具不給法律建議 | 勞資爭議時的證據保存      | 2-3 天     |
| **免費診所地圖**                 | 整合衛福部+NGO 免費醫療資源                            | 資訊整合本身就有價值      | 2 天       |
| **銀行匯款費用比較**             | 列出各銀行對東南亞匯款的手續費                         | 省錢、實用                | 1 天       |
| **二手物資愛心資源地圖**         | 整合教會 / NGO 發放點 + 時間                           | 需要和組織合作維護        | 視合作而定 |

**關鍵問題：** 這些要做成 disaster-handbook 的子頁面，還是另一個網站？

**建議：** 前三個（緊急按鈕、案件紀錄、免費診所）都適合放在 disaster-handbook 底下，因為它們都在「緊急／求助」的概念範圍內。後兩個（匯款、物資）比較偏「生活」，適合獨立。

---

### 🔴 第三批：暫緩（需要專業協助或風險太高）

| 功能                    | 為什麼暫緩                                                    |
| ----------------------- | ------------------------------------------------------------- |
| 勞動契約 OCR + LLM 分析 | 需要法律背景確認翻譯和判讀不會誤導。建議找律師 / 勞動學者合作 |
| 薪資計算器              | 錯一個數字可能讓使用者採信錯誤，要承擔責任                    |
| 詐騙警示資料庫          | 資料來源是警政署，但要每筆確認，錯殺合法業者風險大            |
| 身心諮詢服務            | 需要專業心理師，我們只能「指向」現有服務                      |
| 自動報平安簡訊          | 需要伺服器送簡訊，有成本；不如教使用者用 LINE / 1991          |

---

### ⚪ 第四批：跳過（別人做得更好）

| 功能         | 誰已經在做                          |
| ------------ | ----------------------------------- |
| 中文學習教材 | One-Forty Migrant School            |
| 移工故事媒體 | 4-Way Voice 四方報 / 燦爛時光       |
| 勞權法律諮詢 | 1955 專線 + TIWA / 新事社會服務中心 |
| 多語生活資訊 | 勞動部「移點通」LINE@               |
| 公車路線查詢 | Google Maps                         |

**對這些的做法：** 在我們的網站上列出連結和使用教學，引導使用者去他們的平台。

## 決策路徑

### 如果你的時間有限（1-2 週內）

**只做第一批的前 3 個：**

1. 移工模式開關
2. PDF 加入 1955 / 113 / 辦事處
3. 急診求助詞彙卡

**理由：** 這是延伸現有手冊，不需要新頁面，3-4 天可完成並上線，合作組織看到雛形後才好給具體建議。

### 如果你有 1 個月

**第一批全部 + 獨立「離線緊急按鈕頁」**

這個組合是「預備 + 即時」雙軸：

- 平時：填表產生手冊
- 緊急時：打開就是大按鈕

### 如果你有 1 季

**第一批 + 第二批前三個 + 主動接觸合作組織**

這時候已經有足夠內容可以正式「推廣」給移工社群。在推廣前，值得：

1. 和 Hope Workers' Center / One-Forty 開 1-2 次會
2. 做 5-10 位移工朋友的 user testing
3. 根據回饋修正，不是憑我們想像

## 技術架構建議

**如果要把「移工模式」加進手冊：**

```
HouseholdForm {
  ...既有欄位
  isMigrant: boolean        // 新欄位
  nationality: string       // 已有，但之前沒用
  employer: {               // 新欄位
    name, phone, industry
  }
  broker: {                 // 新欄位
    name, phone
  }
}
```

PDF 輸出時：

- 如果 `isMigrant`：插入移工專屬頁
- 否則：不插入，維持原本排版

優點：**不破壞現有使用者體驗**，只對勾選的人顯示額外內容。

---

## 不該做的 anti-pattern

1. ❌ **把所有功能塞進同一個表單** — 會讓非移工使用者覺得表單太長
2. ❌ **主動代使用者做法律判斷** — 我們只能指向資源，不能給建議
3. ❌ **重做別人已經做得好的東西** — 學習教材、故事媒體
4. ❌ **承諾我們做不到的服務** — 「我們會幫你聯絡雇主」「我們會保護你的隱私」
5. ❌ **做了不維護** — 詐騙警示、物資資源這類需要持續更新的東西，如果沒人維護就不要做

## 回到實際問題

**你現在需要做的決定：**

**Q1：第一批 6 個功能全做，還是先做 3 個核心？**

- 全做：3-4 天，比較完整
- 3 個：1-2 天，更快上線驗證

**Q2：要不要同時做「離線緊急按鈕頁」？**

- 做：多 1 天，但是實用性最高的單一功能
- 不做：專注延伸現有手冊

**Q3：要等合作組織回覆再決定功能，還是先做雛形？**

- 先做：可以當作和合作組織談話的起點
- 先等：避免做白工，但可能等很久

**我的建議：** Q1 全做、Q2 做、Q3 先做雛形。理由：雛形就算事後要改也只是調整，遠比等一個月等不到回覆有效。
